# MAX-чат на GREEN-API

Веб-интерфейс для переписки в мессенджере MAX через [GREEN-API](https://green-api.com/max):
вход по данным инстанса, создание чата по номеру телефона, отправка и приём текстовых сообщений.
Внешний вид повторяет чат [web.max.ru](https://web.max.ru/).

React 18 + TypeScript + Vite, без бэкенда — браузер обращается к GREEN-API напрямую. Логика разбора уведомлений покрыта тестами (Vitest).

## Быстрый старт

```bash
git clone <ссылка-на-репозиторий>
cd max-chat
npm install
npm run dev
```

Приложение откроется на <http://localhost:5173>.

Сборка и локальный просмотр продакшен-версии:

```bash
npm run build
npm run preview
```

Проверка типов и тесты:

```bash
npm run typecheck
npm test
```

Команда `npm run build` выполняет `tsc --noEmit` перед сборкой, поэтому ошибка типов ломает сборку.

Требуется Node.js 18 или новее.

## Как пользоваться

1. **Привяжите телефон к инстансу** в [личном кабинете GREEN-API](https://console.green-api.com) — это делается один раз, до открытия чата (кнопка «Авторизовать инстанс» / QR-код в кабинете).
2. **Вход в чат.** Введите `idInstance` и `apiTokenInstance` этого инстанса. Приложение проверит методом `GetStateInstance`, что инстанс авторизован, и включит уведомления по HTTP API (`SetSettings`: пустой `webhookUrl`, `incomingWebhook: yes`, `outgoingWebhook: yes`). Если инстанс не авторизован, форма покажет понятную ошибку с указанием, что нужно сделать в личном кабинете.
3. **Новый чат.** Введите номер получателя — `79991234567`, `+7 999 123-45-67` или `8 999 123-45-67`. Номер приводится к `79991234567@c.us`. Можно вставить и готовый идентификатор чата, включая групповой (`-10000000000000`).
4. **Переписка.** Напишите сообщение и нажмите Enter (Shift+Enter — перенос строки). Ответ получателя появится в чате автоматически, обновлять страницу не нужно.

Учётные данные и история переписки хранятся в `localStorage` этого браузера и никуда не отправляются. Кнопка «Выйти» удаляет учётные данные.

## Используемые методы API

| Назначение | Метод |
| --- | --- |
| Проверка авторизации инстанса | `GetStateInstance` |
| Настройка приёма уведомлений | `GetSettings`, `SetSettings` |
| Отправка сообщения | [`SendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/) |
| Приём уведомлений | [`ReceiveNotification`](https://green-api.com/v3/docs/api/receiving/technology-http-api/ReceiveNotification/) |
| Подтверждение обработки | [`DeleteNotification`](https://green-api.com/v3/docs/api/receiving/technology-http-api/DeleteNotification/) |

Запросы идут по унифицированному адресу `{apiUrl}/waInstance{idInstance}/{method}/{apiTokenInstance}`; необязательный префикс `v3` не используется.

## Как устроен приём сообщений

`src/hooks/useNotifications.js` держит бесконечный цикл:

1. `ReceiveNotification` с `receiveTimeout=10` — long polling, соединение висит до появления уведомления;
2. уведомление разбирается и попадает в состояние приложения;
3. `DeleteNotification` подтверждает обработку и удаляет уведомление из очереди.

Следующий запрос уходит только после подтверждения предыдущего, поэтому порядок FIFO сохраняется и сообщения не теряются. При ошибке сети цикл ждёт 5 секунд и повторяет попытку; индикатор в шапке списка чатов показывает состояние соединения. Цикл останавливается через `AbortController` при выходе из аккаунта.

Обрабатываются уведомления `incomingMessageReceived`, `outgoingMessageReceived`, `outgoingAPIMessageReceived` (типы `textMessage` и `extendedTextMessage`) и `outgoingMessageStatus` — по нему обновляется статус отправленного сообщения (отправлено / доставлено / прочитано / не отправлено). Нетекстовые сообщения игнорируются по условию задания.

## Структура проекта

```
src/
  types.ts                    модели чатов и типы ответов API
  api/greenApi.ts             запросы к GREEN-API и разбор ошибок
  api/instance.ts             включение уведомлений по HTTP API
  hooks/useNotifications.ts   цикл ReceiveNotification → DeleteNotification
  components/LoginScreen.tsx  вход по учётным данным (инстанс должен быть уже авторизован)
  components/Sidebar.tsx      список чатов и создание нового
  components/ChatWindow.tsx   лента сообщений и поле ввода
  utils/chat.ts               номера, chatId, даты, разбор уведомлений
  utils/chat.test.ts          тесты разбора (Vitest)
  utils/storage.ts            localStorage
  styles.css                  оформление
```

## Тесты

`npm test` проверяет чистые функции, от которых зависит корректность переписки: нормализацию номеров и построение `chatId`, форматирование заголовка чата, извлечение текста из `textMessage` и `extendedTextMessage`, а также преобразование уведомлений в сообщения — включая случаи, которые нужно игнорировать (`outgoingMessageStatus`, `stateInstanceChanged`, нетекстовые типы, уведомление без `chatId`).

## Развёртывание

Статическая сборка `dist/` подходит для любого хостинга: Vercel, Netlify, GitHub Pages, Cloudflare Pages.

- Vercel / Netlify: команда сборки `npm run build`, каталог `dist`.
- GitHub Pages: `npm run build` и публикация `dist` (в `vite.config.js` уже задан относительный `base: './'`).

Сервер не нужен: ключи вводит сам пользователь, запросы идут из браузера.

## Ограничения

- Только текстовые сообщения — как требует задание.
- Один инстанс обслуживает один открытый экземпляр приложения: уведомление, прочитанное в одной вкладке, удаляется из очереди и не придёт в другую.
- Отправка возможна на номера, зарегистрированные в MAX; иначе GREEN-API вернёт `200` и `idMessage`, но придёт статус `failed` — он отображается под сообщением.
- Токен живёт в браузере пользователя. Для продакшена запросы стоит проксировать через собственный бэкенд.
